Internal extensions

These bindings are not exported and are version-sensitive implementation details. Qualify them with PowerSimulationsDecomposition when inspecting them. Prefer the public API for user code.

PowerSimulationsDecomposition.DecompositionAlgorithm — Type
DecompositionAlgorithm

Identify the internal dispatch family for regional container algorithms.

source
PowerSimulationsDecomposition.SequentialAlgorithm — Type
SequentialAlgorithm

Build regional containers and solve each once per model execution.

Iteration follows the subproblem dictionary. This internal algorithm aggregates results only after all regional solves succeed; it has no convergence loop.

source
PowerSimulationsDecomposition.MPIParallelAlgorithm — Type
MPIParallelAlgorithm

Identify the incomplete internal MPI (Message Passing Interface) execution scaffold.

The solve method contains unresolved names and does not provide a supported parallel execution path.

source
PowerSimulationsDecomposition.MultiOptimizationContainer — Type
MultiOptimizationContainer(algorithm, sys, settings, time_series_type, subproblem_keys)

Create the internal regional PSI containers and joint optimization stores.

The algorithm argument is a concrete DecompositionAlgorithm type. Each key identifies a regional container; bus maps are populated during the build. The System must provide a single time-series resolution and the time-series type must be concrete. Initialization sets the System's units to SYSTEM_BASE. The main container is not a solved central coordination problem.

source
PowerSimulationsDecomposition.StateEstimationInjections — Type
StateEstimationInjections

Identify internal baseline nodal-injection parameters on PSY.ACBus.

Values initialize to zero with unit multipliers and use bus-number strings and time indices. Simulation updates read ActivePowerBalance expression state in system-base per-unit quantities. No general resampling contract is implemented.

source
PowerSimulationsDecomposition.StateEstimationFlows — Type
StateEstimationFlows

Identify internal baseline flow parameters on PSY.MonitoredLine.

Values initialize to zero with unit multipliers and use branch names and time indices. Simulation updates read PTDFBranchFlow expression state in system-base per-unit quantities.

Sequential construction, solution, and results

PowerSimulationsDecomposition.build_impl! — Function
build_impl!(
    container::PowerSimulationsDecomposition.MultiOptimizationContainer{PowerSimulationsDecomposition.SequentialAlgorithm},
    template::MultiProblemTemplate,
    sys::PowerSystems.System
)

build_impl!(container::MultiOptimizationContainer{SequentialAlgorithm},
            template::MultiProblemTemplate, sys::PSY.System)

Build each regional optimization problem and validate the resulting containers.

Use each regional template to populate its corresponding optimization container, then populate bus maps and validate component membership with build_main_problem!. Check both regional and main optimization containers through PowerSimulations and return nothing.

Regional traversal follows dictionary iteration, not sorted subsystem order. Propagate construction and validation errors; do not solve the problems or allocate the joined result arrays here.

source
PowerSimulationsDecomposition.build_main_problem! — Function
build_main_problem!(
    container::PowerSimulationsDecomposition.MultiOptimizationContainer{PowerSimulationsDecomposition.SequentialAlgorithm},
    template::MultiProblemTemplate,
    sys::PowerSystems.System
)

build_main_problem!(container::MultiOptimizationContainer{SequentialAlgorithm},
                    template::MultiProblemTemplate, sys::PSY.System)

Populate regional bus-number maps and validate modeled component membership.

Store the available AC bus numbers for each region in container.subproblem_bus_map. Require each available modeled static injector to share its subsystem with its attached bus. When an HVDC model is configured, require both terminal buses of each available regional HVDC component to belong to that region.

Throw IS.ConflictingInputsError for inconsistent membership and return nothing otherwise. Despite its name, this method does not construct a central optimization problem or assign components to subsystems.

source
PowerSimulationsDecomposition.write_results_to_main_container — Function
write_results_to_main_container(
    container::PowerSimulationsDecomposition.MultiOptimizationContainer
)

write_results_to_main_container(container::MultiOptimizationContainer)

Evaluate and copy regional results into the joined stores of container.

Copy assigned entries from dense one-, two-, and three-dimensional variable, auxiliary-variable, constraint, expression, and dual arrays. Use regional bus maps for nodal active-power-balance columns. Also copy parameter values and multipliers, which support only one or two dimensions.

The destination keys and arrays must already exist. Preserve the stored units, flow signs, and time indexing; do not resample or convert power bases. Return nothing.

Notes

  • Skip SparseAxisArray results and do not copy other dense dimensionalities.
  • Raise an error for parameter arrays with more than two dimensions.
  • Overlapping regional axes can overwrite previously copied entries; dictionary iteration does not define a coordination order.
  • Copy into joined result stores, not into a solved central optimization model.

PowerSimulationsDecomposition.solve_impl! — Function
solve_impl!(
    container::PowerSimulationsDecomposition.MultiOptimizationContainer{PowerSimulationsDecomposition.SequentialAlgorithm},
    sys::PowerSystems.System
) -> Any

solve_impl!(container::MultiOptimizationContainer{SequentialAlgorithm},
            sys::PSY.System)

Solve regional optimization problems sequentially and join successful results.

Call PowerSimulations' solve implementation for each regional container in dictionary iteration order. Return immediately with the first status other than ISSIM.RunStatus.SUCCESSFULLY_FINALIZED, without joining results.

After every regional solve succeeds, call write_results_to_main_container and return the last regional status. Return ISSIM.RunStatus.RUNNING when there are no regional problems. Do not solve a central coordination model or perform an iterative convergence loop.

PowerSimulations.set_service_model! — Method
set_service_model!(
    template::MultiProblemTemplate,
    model::PowerSimulations.ServiceModel,
    subsystem_id::String
)

PSI.set_service_model!(template::MultiProblemTemplate,
                       model::PSI.ServiceModel{<:PSY.Service, <:PSI.AbstractServiceFormulation},
                       subsystem_id::String)

Store model in the base and a deep copy in the requested regional template.

When subsystem_id matches a regional key, first mutate the supplied model's subsystem to that key, then copy it into that region. Other regions are left unchanged. The base retains the supplied object by reference.

An unknown key does not raise an error: only the base entry is set, and the supplied model's subsystem is unchanged. Return nothing.

finalize_template!(

finalize_template!(template::MultiProblemTemplate, sys::PSY.System)

Finalize the base and regional templates against sys in place.

Use upstream finalization for the base, then apply subsystem-aware finalization to each regional template. Populate service associations and remove regionally empty device and branch models without assigning System components. Return nothing and propagate upstream errors.

finalize_template!(template::PSI.ProblemTemplate, sys::PSY.System,

Finalize one regional template using available components in subsystem.

Remove branch and device models with no available regional components and register retained AC branch types with the network model. Populate aggregated service models, contributing devices, and device/service associations through the upstream helpers.
