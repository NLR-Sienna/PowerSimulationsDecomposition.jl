Configure security-constrained reserves

Create generator outages, explicitly select monitoring coverage, and configure the responding service with SecurityConstrainedRampReserve. Follow setup and subsystem assignment first. The runnable example needs the docs environment's solver and case-builder data.

Separate failure, response, and monitoring

  • The outaged generator loses generation in the contingency.
  • The responding reserve service supplies the modeled replacement power.
  • The monitored components have their post-contingency behavior modeled; they are not additional failed equipment.

Attach the same outage attribute to the failed generator and its responding service within a System. Register a matching named security-constrained ServiceModel. A generator attachment alone does not select a responding service.

An empty monitoring set is not shorthand for all components. PowerSystems accepts an empty set without defining its downstream meaning. In resolved PSI, an empty set warns and contributes no post-contingency variables or constraints. A successful solve alone does not establish contingency coverage.

Choose the monitoring scope

"All" means all eligible, available, actually modeled components in the consuming model, not all devices present in the System.

StudySelectionBoundary
Small full-system referenceExplicitly enumerate all eligible modeled AC branchesUseful for validating coverage and comparing restricted selections
Regional modelSelect eligible branches owned and modeled by that regionRespect branch/network filters; include eligible boundary branches
Large targeted studySelect outage/monitor pairs justified by the studyDocument exclusions; unmonitored branches have no security coverage claim
Whole-system coverage through regional modelsVerify coverage across consuming regional modelsDo not copy a global branch list blindly into every region

More outage/monitor pairs increase construction, solve, and storage work. A subset reduces study coverage; it does not retain an all-branch guarantee. Monitoring every branch for one generator outage is not enumeration of all outages.

All eligible regional branches

The example models Line and MonitoredLine, without additional branch filters, and assigns branches by from-bus area. Under those explicit assumptions:

monitored_branches = collect(
    get_components(ACTransmission, sys; subsystem_name="a"),
)
@assert all(get_available, monitored_branches)
@assert all(branch -> branch isa Union{Line, MonitoredLine}, monitored_branches)
@assert !isempty(monitored_branches)

For another template, restrict the list to supported modeled types and effective branch/network filters. Membership alone does not prove eligibility. Omit the subsystem restriction for a full-system model only after verifying eligibility against that model. A branch's presence in regional PTDF network context does not automatically make it an eligible regional monitor.

A selected subset

Start from the verified eligible list and reject missing requested names:

eligible_by_name = Dict(get_name(branch) => branch for branch in monitored_branches)
selected_names = ["1_1"]
@assert all(name -> haskey(eligible_by_name, name), selected_names)
selected_branches = [eligible_by_name[name] for name in selected_names]

Do not silently intersect an invalid request with available branches: that silently changes the study's requested coverage.

Describe and attach outages

The script defines three example-local helpers, not exported package APIs:

  • assign_example_subsystems! assigns areas, buses, injections, and branches.
  • make_outage_specifications returns typed named tuples describing failed generator names, responding reserve types/names, and explicit monitor names.
  • add_outages_to_systems! resolves the specifications separately in each System and attaches one outage object to its generators and services.

For example, this specification selects one monitored line rather than all eligible lines. Use it instead of that region's all-branch specification in a fresh run, not as an additional duplicate outage:

specification = (
    outage_generators=["Sundance_1"],
    responding_reserves=Dict{DataType, String}(VariableReserve{ReserveUp} => "Reserve1_1"),
    monitored_components=["1_1"],
)

Monitoring names in these helper specifications are resolved to actual devices before GeometricDistributionForcedOutage is constructed. The PowerSystems constructor accepts device objects or UUIDs and stores UUIDs internally. Resolve components in each independently created System: matching names do not guarantee matching UUIDs. Preserve the reserve's contributing-device associations and assign/register its service in the intended region.

Configure before constructing the DecisionModel

To replace an existing outage's monitoring set before model construction:

set_monitored_components!(outage, selected_branches)

add_monitored_components! adds to the current set; clear_monitored_components! empties it and does not enable all-component monitoring. These are PowerSystems APIs.

After constructing a DecisionModel, recreate it from the updated System and template if monitoring changes. Regional finalization has already populated outage metadata; changing the System does not refresh that metadata or existing constraints. Users should not call PSI's internal metadata builders themselves.

Run the complete example

The script follows the active two-area 10-bus regression. It uses dispatch, not unit commitment. Region a monitors six internal lines and inter_area_line; b monitors six internal lines.

The fixture removes thermal ramp limits and makes both Sundance generators must-run at a minimum of 1.0 system-base p.u. These demonstration assumptions isolate contingency/export behavior; they are not production operating data or proof of central/decomposed equivalence. Outage parameters are fixture values, not a stochastic reliability simulation.

From the repository root:

julia --project=docs docs\examples\security_constrained_reserves.jl
# Checked two generator outages, 13 monitored branch/outage pairs, and 24 hourly results.

The script checks successful build/solve statuses, exact outage/branch identities, all 24 time indices, finite flows, and reserve-deployment conservation. The raw standalone values used by its checks are system-base p.u.; see contingency results.

using Dates
using HiGHS
using JuMP
import InfrastructureSystems as IS
using PowerSimulations
using PowerSimulationsDecomposition
using PowerSystemCaseBuilder
using PowerSystems

"""
    assign_example_subsystems!(sys::System, area_to_subsystem::Dict{String, String})

Assign areas, buses, injections, and AC branches using this example's from-bus policy.
"""
function assign_example_subsystems!(sys::System, area_to_subsystem::Dict{String, String})
    for subsystem in unique(collect(values(area_to_subsystem)))
        add_subsystem!(sys, subsystem)
    end
    # Area membership does not propagate to buses or their attached devices.
    for area in get_components(Area, sys)
        add_component_to_subsystem!(sys, area_to_subsystem[get_name(area)], area)
    end
    for bus in get_components(ACBus, sys)
        subsystem = area_to_subsystem[get_name(get_area(bus))]
        add_component_to_subsystem!(sys, subsystem, bus)
    end
    for device in get_components(StaticInjection, sys)
        subsystem = area_to_subsystem[get_name(get_area(get_bus(device)))]
        add_component_to_subsystem!(sys, subsystem, device)
    end
    # Ownership selects the regional model; it does not reverse branch flow signs.
    for branch in get_components(ACTransmission, sys)
        subsystem = area_to_subsystem[get_name(get_area(get_from(get_arc(branch))))]
        add_component_to_subsystem!(sys, subsystem, branch)
    end
    return
end

"""
    make_outage_specifications(sys::System)

Describe each generator outage, responding reserve, and explicit monitored branch set.
"""
function make_outage_specifications(sys::System)
    specifications = @NamedTuple{
        outage_generators::Vector{String},
        responding_reserves::Dict{DataType, String},
        monitored_components::Vector{String},
    }[]
    for (subsystem, generator_name, reserve_name) in
        (("a", "Sundance_1", "Reserve1_1"), ("b", "Sundance_2", "Reserve1_2"))
        # All regional branches are eligible here: both types are modeled without filters.
        monitored_branches =
            collect(get_components(ACTransmission, sys; subsystem_name=subsystem))
        @assert all(get_available, monitored_branches)
        @assert all(
            (branch::ACTransmission) -> branch isa Union{Line, MonitoredLine},
            monitored_branches,
        )
        @assert !isempty(monitored_branches)
        push!(
            specifications,
            (
                outage_generators=[generator_name],
                responding_reserves=Dict{DataType, String}(
                    VariableReserve{ReserveUp} => reserve_name,
                ),
                monitored_components=get_name.(monitored_branches),
            ),
        )
    end
    return specifications
end

"""
    add_outages_to_systems!(systems::Vector{System}, outage_specifications)

Resolve each specification in each System and attach its outage to generators and reserves.
"""
function add_outages_to_systems!(
    systems::Vector{System},
    outage_specifications::Vector{
        @NamedTuple{
            outage_generators::Vector{String},
            responding_reserves::Dict{DataType, String},
            monitored_components::Vector{String},
        }
    },
)
    for specification in outage_specifications
        for sys in systems
            # Resolve objects per System: names can match even when component UUIDs differ.
            monitored_components = [
                get_component(ACTransmission, sys, name) for
                name in specification.monitored_components
            ]
            @assert !isempty(monitored_components)
            @assert all(
                (component::Union{Nothing, ACTransmission}) -> !isnothing(component),
                monitored_components,
            )
            outage = GeometricDistributionForcedOutage(;
                mean_time_to_recovery=10.0,
                outage_transition_probability=1.0,
                monitored_components=monitored_components,
            )
            for generator_name in specification.outage_generators
                generator = get_component(PowerSystems.Generator, sys, generator_name)
                add_supplemental_attribute!(sys, generator, outage)
            end
            # The same attribute links failed equipment to its responding service.
            for (reserve_type, reserve_name) in specification.responding_reserves
                reserve = get_component(reserve_type, sys, reserve_name)
                add_supplemental_attribute!(sys, reserve, outage)
            end
        end
    end
    return
end

# 1. Load forecast-backed data and assign regional membership explicitly.
sys = build_system(PSISystems, "two_area_pjm_DA"; add_reserves=true)
area_to_subsystem = Dict("Area1" => "a", "Area2" => "b")
assign_example_subsystems!(sys, area_to_subsystem)

# 2. Isolate the fixture's contingency behavior, not realistic ramp-limited operation.
for generator in get_components(ThermalStandard, sys)
    set_ramp_limits!(generator, nothing)
end
for generator_name in ("Sundance_1", "Sundance_2")
    generator = get_component(ThermalStandard, sys, generator_name)
    set_must_run!(generator, true)
    set_active_power_limits!(generator, (min=1.0, max=2.0))
end

# 3. Declare modeled branch types before choosing their monitoring coverage.
template = MultiProblemTemplate(NetworkModel(SplitAreaPTDFPowerModel), ["a", "b"])
set_device_model!(template, ThermalStandard, ThermalBasicDispatch)
set_device_model!(template, PowerLoad, StaticPowerLoad)
set_device_model!(template, Line, StaticBranch)
set_device_model!(template, MonitoredLine, StaticBranch)

# 4. Specify and attach outages before DecisionModel finalizes their metadata.
outage_specifications = make_outage_specifications(sys)
add_outages_to_systems!([sys], outage_specifications)
@assert length(outage_specifications[1].monitored_components) == 7
@assert length(outage_specifications[2].monitored_components) == 6

# 5. Assign each responding service and register its security-constrained formulation.
for (subsystem, reserve_name) in (("a", "Reserve1_1"), ("b", "Reserve1_2"))
    reserve = get_component(VariableReserve{ReserveUp}, sys, reserve_name)
    add_component_to_subsystem!(sys, subsystem, reserve)
    set_service_model!(
        template,
        ServiceModel(
            VariableReserve{ReserveUp},
            SecurityConstrainedRampReserve,
            reserve_name,
        ),
        subsystem,
    )
end

# 6. Build and solve the hourly dispatch; this is not a unit-commitment formulation.
problem = DecisionModel(
    MultiRegionProblem,
    template,
    sys;
    name="RegionalSecurityConstrainedDispatch",
    horizon=Hour(24),
    interval=Hour(1),
    resolution=Hour(1),
    optimizer=optimizer_with_attributes(HiGHS.Optimizer, "log_to_console" => false),
)
@assert build!(problem; output_dir=mktempdir()) == PowerSimulations.ModelBuildStatus.BUILT
@assert solve!(problem) == PowerSimulations.RunStatus.SUCCESSFULLY_FINALIZED
results = OptimizationProblemResults(problem)

# 7. Check exported sparse flows and reserve conservation, not merely solve success.
for specification in outage_specifications
    reserve_type, reserve_name = only(specification.responding_reserves)
    reserve = get_component(reserve_type, sys, reserve_name)
    outage = only(get_supplemental_attributes(GeometricDistributionForcedOutage, reserve))
    flow_key = PowerSimulations.ExpressionKey{
        PostContingencyBranchFlow,
        VariableReserve{ReserveUp},
    }(
        reserve_name,
    )
    deployment_key = PowerSimulations.VariableKey{
        PostContingencyActivePowerReserveDeploymentVariable,
        VariableReserve{ReserveUp},
    }(
        reserve_name,
    )
    flows = get_expression_values(results)[flow_key]
    deployment = get_variable_values(results)[deployment_key]
    # Raw standalone tables encode outage UUID and branch in one name; values are p.u.
    outage_id = string(IS.get_uuid(outage))
    expected_names =
        Set(outage_id * "__" * name for name in specification.monitored_components)
    @assert Set(flows.name) == expected_names
    @assert Set(flows.time_index) == Set(1:24)
    @assert size(flows, 1) == 24 * length(expected_names)
    @assert all(isfinite, flows.value)
    for time_index in 1:24
        @assert count(==(time_index), flows.time_index) == length(expected_names)
        @assert isapprox(
            sum(deployment.value[deployment.time_index .== time_index]),
            1.0;
            atol=1e-6,
        )
    end
end
println(
    "Checked two generator outages, 13 monitored branch/outage pairs, and 24 hourly results.",
)

Adapt the monitoring policy

The RTS regression monitors CA-1 and A28 for the outage of 313_CC_1 and response service Spin_Up_R3. Its existing to-bus ownership assigns both lines to subsystem a, containing areas 1 and 3; CB-1 and AB1 belong to b. That is different from the example's from-bus policy. Do not assume internal-only monitoring or reverse branch orientation to change ownership.

RTS checks five realized flow rows against solved regional expressions in MW and preserves reserve-deployment conservation checks. Its in-memory multistage configuration does not establish support for every storage/realized-reader path.

Troubleshoot missing coverage

SymptomCheck and recovery
Empty-monitor warningSupply a nonempty explicit eligible set; empty does not mean all
No deployment or flow keyCheck generator/service attachments and the matching named security-constrained service model
Missing branch or monitorCheck availability, modeled types, filters, ownership, and System UUID identity; recreate the model
Warning about an unmodeled responding serviceRegional validation can see another region's service; verify the intended region's keys and coverage rather than dismissing all warnings
Missing AreaInterchange monitor under PTDFThat path does not build these tie-flow expressions; see the network-specific reference
