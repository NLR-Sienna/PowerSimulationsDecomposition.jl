Security-constrained integration

PowerSystems owns outage attributes and monitored-component identities; PowerSimulations owns security-constrained reserve and branch formulations. This package finalizes metadata for regional templates and joins their solved results. It does not introduce a new security-constrained formulation. Use the how-to for executable setup.

Selection contracts

Outage selection and monitoring selection are separate: failed equipment is identified by outage attachments, while monitored_components requests the devices whose post-contingency behavior is modeled. Selecting every monitor for one outage does not enumerate every possible contingency or prove N-1 security.

ConsumerOutage selectionBoundary in resolved PSI
Security-constrained reserve serviceOutages attached to the named service with a matching SC ServiceModelUpward reserves only; monitor eligibility depends on network formulation
Upstream SC branch device modelOutages attached to equipment types covered by an SC device model; explicit selection can restrict discoveryEligible modeled AC transmission monitors need not themselves use SC device formulations

The runnable example and active deliverability tests cover generator outages with SecurityConstrainedRampReserve. The branch-device row describes the upstream contract, not a tested regional line-outage recipe or a blanket compatibility claim for every formulation.

PowerSystems permits empty monitoring without assigning its downstream meaning. Resolved PSI warns and skips outages with empty sets. Missing monitored UUIDs or unsupported/unmodeled monitored types can be warned about and skipped; other scope mismatches can fail at construction. Check actual result coverage, not only successful construction.

Network scope and limits

For PTDF models, select available AC branches actually represented by the consuming regional template and its filters. External buses in regional PTDF context do not make all external branches eligible monitors. Ownership does not reverse the branch flow sign.

AreaInterchange is not an AC transmission branch. In the inspected upstream reserve-service AreaBalancePowerModel path, a monitored tie must be available, in network scope, and included in the template's AreaInterchange device model. Under PTDF, PSI warns and drops these monitors because it does not construct their post-contingency tie-flow expressions. This upstream distinction does not extend interchange monitoring to the split-PTDF example.

Requesting a monitored flow is not proof that its physical rating is enforced. Check the applicable upstream contingency constraints, limits, and branch/network formulations. Neither StaticBranchUnbounded nor this package's StaticBranchUnboundedStateEstimation should be presented as ordinary thermal-rating enforcement. Flow comparisons and reserve conservation do not constitute an all-branch security theorem.

Planned outages

The example uses GeometricDistributionForcedOutage. Resolved PSI skips planned outages attached to SC reserve services unless that service model opts into "include_planned_outages". SC branch models also skip planned outages during automatic discovery unless enabled, but explicitly listed outage UUIDs bypass that discovery filter. Do not transfer one consumer's selection rules to another.

Regional lifecycle

Configure membership, branch filters, service associations, and monitors before constructing the DecisionModel:

flowchart TD
    scA["Failed equipment and responding service"] --> scC["Attach outage with explicit eligible monitors"]
    scB["Regional membership and template filters"] --> scC
    scC --> scD["DecisionModel finalizes outage metadata"]
    scD --> scE["Build regional contingency entries"]
    scE --> scF["Solve regional models"]
    scF --> scG["Copy values using actual sparse tuple keys"]
    scG --> scH["PSI storage and result readers"]

Regional finalize_template! delegates metadata to PSI after preparing model and service associations. Joining preserves actual sparse (outage UUID, branch name, time index) entries, not every Cartesian combination. It adds no regional result axis and does not resolve overlapping ownership. Recreate the model after changing monitoring; mutating the System does not rebuild finalized metadata or existing constraints.
