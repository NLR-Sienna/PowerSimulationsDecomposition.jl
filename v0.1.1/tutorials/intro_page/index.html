Two-region dispatch

Build a small regional dispatch model, solve it, and verify the joined thermal generation results. Follow setup first. This example is adapted from test/test_component_assignment.jl, not from an exported partitioning helper.

Scope and assumptions

The PowerSystemCaseBuilder two_area_pjm_DA fixture has two areas. This example assigns areas, their buses, and static injections to subsystems a and b. It assigns each AC transmission branch to the subsystem of its from bus, matching the component-assignment test's example policy.

The model uses ThermalBasicDispatch, not unit commitment. Reserve data are loaded with the fixture, as in the test, but no reserve service is modeled here. There is no AreaInterchange model or inter-stage state producer in this tutorial: state-estimation injections start at zero and each area's balance is enforced locally. This is a runnable construction/aggregation example, not an equivalent solution of a centrally coordinated market or an accuracy study.

Execute the example

The complete script uses public PowerSystems/PowerSimulations APIs and the two exported decomposition entry points. It does not include test utilities. From the repository root:

julia --project=docs docs\examples\decomposition.jl

The complete script below is read directly from docs/examples/decomposition.jl during each documentation build, including its comments. Editing the script updates this listing without editing this page. The build also executes that same file and checks its assertions.

using Dates
using HiGHS
using JuMP
using PowerSimulations
using PowerSimulationsDecomposition
using PowerSystemCaseBuilder
using PowerSystems

# Load forecast data; the fixture's reserve services are not modeled in this example.
sys = build_system(PSISystems, "two_area_pjm_DA"; add_reserves=true)
area_to_subsystem = Dict("Area1" => "a", "Area2" => "b")

# Create named membership groups, not independent copies of the System.
for subsystem in ("a", "b")
    add_subsystem!(sys, subsystem)
end
# Assign areas and buses separately: area membership does not propagate to buses.
for area in get_components(Area, sys)
    add_component_to_subsystem!(sys, area_to_subsystem[get_name(area)], area)
end
for bus in get_components(ACBus, sys)
    add_component_to_subsystem!(sys, area_to_subsystem[get_name(get_area(bus))], bus)
end
# Keep each generator/load in the same subsystem as its attached bus.
for device in get_components(StaticInjection, sys)
    subsystem = area_to_subsystem[get_name(get_area(get_bus(device)))]
    add_component_to_subsystem!(sys, subsystem, device)
end
# Choose from-bus ownership for AC branches without changing their flow direction.
for branch in get_components(ACTransmission, sys)
    from_bus = get_from(get_arc(branch))
    subsystem = area_to_subsystem[get_name(get_area(from_bus))]
    add_component_to_subsystem!(sys, subsystem, branch)
end

# Configure regional dispatch models; this formulation does not perform unit commitment.
template = MultiProblemTemplate(NetworkModel(SplitAreaPTDFPowerModel), ["a", "b"])
set_device_model!(template, ThermalStandard, ThermalBasicDispatch)
set_device_model!(template, PowerLoad, StaticPowerLoad)
set_device_model!(template, Line, StaticBranch)
set_device_model!(template, MonitoredLine, StaticBranch)

# Solve a 24-hour window at hourly resolution, using HiGHS in each region.
problem = DecisionModel(
    MultiRegionProblem,
    template,
    sys;
    name="RegionalDispatch",
    horizon=Hour(24),
    interval=Hour(1),
    resolution=Hour(1),
    optimizer=optimizer_with_attributes(HiGHS.Optimizer, "log_to_console" => false),
)
# Build into temporary storage and require successful statuses before reading values.
output_dir = mktempdir()
@assert build!(problem; output_dir=output_dir) == PowerSimulations.ModelBuildStatus.BUILT
@assert solve!(problem) == PowerSimulations.RunStatus.SUCCESSFULLY_FINALIZED

# Read joined regional dispatch with a typed key; standalone string lookup is incomplete.
results = OptimizationProblemResults(problem)
dispatch = read_variable(
    results,
    ActivePowerVariable,
    ThermalStandard;
    table_format=TableFormat.WIDE,
)
# Check every thermal generator and hourly row, allowing only numerical feasibility noise.
generator_names = sort!([get_name(g) for g in get_components(ThermalStandard, sys)])
@assert size(dispatch, 1) == 24
@assert sort!(filter(!=("DateTime"), names(dispatch))) == generator_names
dispatch_values = Matrix(dispatch[:, generator_names])
@assert all(isfinite, dispatch_values)
@assert minimum(dispatch_values) >= -1e-6
println("Solved two regional dispatch models; checked 24 rows and all thermal generators.")

What the script does

  1. Load a forecast-backed fixture; create the two named subsystems.
  2. Explicitly add areas, buses, static injections, and AC branches to them.
  3. Construct MultiProblemTemplate(NetworkModel(SplitAreaPTDFPowerModel), ["a", "b"]).
  4. Use PSI's set_device_model! methods to populate the base and regional templates.
  5. Construct DecisionModel(MultiRegionProblem, template, sys; ...) with a 24-hour horizon, one-hour interval, and one-hour resolution.
  6. Assert ModelBuildStatus.BUILT and RunStatus.SUCCESSFULLY_FINALIZED.
  7. Read ActivePowerVariable__ThermalStandard in wide format and assert 24 rows, exactly the fixture's thermal-generator columns, finite values, and dispatch above -1e-6 (numerical feasibility tolerance).

That final message is a success check, not a claim about central optimality or regional convergence. Build/solve logs and results are written to a temporary output directory selected by the script.

Adapt it safely

Before changing membership, read Assign subsystems. For inter-stage forecasts and state-estimation flows, read State passing and the formulation library. Use Read results to discover keys instead of assuming every formulation emits the same entries.

To model generator outages and responding reserves, continue with Configure security-constrained reserves. Its separate executable example adds typed outage specifications, explicit regional monitoring, and contingency-result checks without changing this introductory dispatch model.
